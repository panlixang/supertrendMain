## 🔴 先看这里：周期与 tp1_ratio 是一阶参数，入场过滤是二阶

- **`tp1_ratio` 越大收益越差 —— 17/18 格单调**（2 资产 × {1,4,12}h × {3,4,5} 倍）：
  | 剩余仓位 | 18 格收益均值 | 盈亏比均值 |
  |---|---|---|
  | 0%（平100%） | −12.77% | 0.57 |
  | 30%（**平70% = 生产现值**） | +2.23% | 0.65 |
  | 50%（平50%） | +12.37% | 0.72 |
  | 70%（平30%） | **+22.49%** | **0.85** |
  符号检验：剩余50%/70% vs 生产 **各 17/18 变好，p=0.0004**；回撤几乎不变（28.1%→32.9%）。
  **唯一反向的格是 BTC 1h×3.0**（信号本身无边际时，留仓只放大亏损）。
- **机制**：SuperTrend 的价值在「让利润奔跑」；+1.5% 就砍 70% 仓 = 用高胜率低赔率替换趋势跟踪。
- **4h/12h 上「持有到反向翻向」（= 剩余100%）第一次超过买入持有**：
  BTC 4h×5.0 +93.8% vs 买入持有 +80.3%；ETH 12h×3.0 +120.5% vs +16.6%（但回撤 55–65%）。
- **逐年**（BTC 4h×5.0 平30%）：净期望 +0.898/+1.171/+0.565/−0.712/+1.035 → **4/5 年为正，
  胜率稳定 60–80%**（对比简化出场胜率 27–53%，波动大）。
- ❌ **已否定的方向**：ER 分档出场（`er_weak_min`+`exit_rules_quick`，16 格 12 负、一致率 25%）；
  ER 震荡过滤（`--er-abs`）；「剩余 30% 等反向信号平」这条腿（与 `trail_with_st` 逻辑互斥，且修好更差）。

## 📌 外部指标参考：SATS（Self-Aware Trend System）
来源：TradingView / WillyAlgoTrader，脚本 id `sXFWVpmg`，**源码未公开（受保护）**。
拿到的是作者官方说明 + ProRealCode 社区完整移植版（含全部公式与约 30 个默认参数），**非 Pine 原文**，
要动生产需对着原脚本核一遍。六层机制：
1. `effATR = rawATR × (0.5 + 0.5 × ER)` —— **本项目从未测过**
2. `TQI` 四因子加权：ER .35 / 波动 .20 / 结构 .25 / 动量 .20 —— 因子1 就是我们的 `regime.efficiency_ratio`(ER_WINDOW=60)
3. `tqiMult = 1 − q + q × (0.6 + 0.8 × (1−tqi)^1.5)`（curvePower 1.5）
4. 不对称：`active = sym × (1 − asym·tqi·0.3)`、`passive = sym × (1 + asym·tqi·0.4)`，再 EMA(0.15) 平滑
5. character-flip：`prevTQI > .55 且 tqi < .25 且 trendAge ≥ 5` 且本 bar 未价格翻转 → 强制翻向
6. 交易计划 1R/2R/3R 各平 1/3；SL = 枢轴 ± slAtrMult(1.5)×ATR，与本项目 `tp1_pct=1.5%` **口径不同**
关键默认值：`atrLen 14 / baseMult 2.0 / erLen 20 / atrBaselineLen 100 / qualityStrength 0.4 /
asymStrength 0.5 / charFlipMinAge 5`。**baseMult 2.0 偏低，落在我们 m=3.0 那档（ER 方向为负的那档）。**
⚠️ 内部矛盾：effATR 在震荡里砍半，抵消了大部分"震荡加宽"的宣称 ——
chop 净带宽 ≈ `1.45×rawATR` vs 趋势 `1.26×rawATR`，只宽约 15%，不是宣传的"显著变宽"。
不移植：0–102 信号评分、3×3 区制网格、质量强度自校准（50 笔窗口 = 过拟合陷阱）。

### SATS 移植实测（`backend/sl2_sats.py`，2026-09-28，报告 `_diag_sats.txt`）
**全部用生产出场口径**（运行时替换 `BE.super_trend`，见下方工程约定 5）。2 资产 × {1h,4h}：

| 格 | 买入持有 | SATS 六层 | 同宽ST | 生产ST3.0 | 关effATR | C5精炼 | C5同宽ST |
|---|---|---|---|---|---|---|---|
| BTC 1h | +80.5 | **−95.56** | −91.75 | −45.39 | −54.33 | −40.15 | −56.24 |
| BTC 4h | +80.3 | **−41.03** | −47.51 | +1.22 | +24.32 | −15.37 | +20.69 |
| ETH 1h | +17.3 | **−44.05** | −73.74 | −27.23 | −28.71 | −54.06 | −25.06 |
| ETH 4h | +18.2 | **+39.38** | −12.18 | +3.59 | +6.59 | +15.04 | +38.71 |

（ETH 4h 只有 0.68 年样本；BTC 4h 1.18 年）

- **① 它不是新策略**：名义 `baseMult=2.0`，但带宽 = 乘数 × **effATR**，
  实测有效宽度只有 **1.30~1.31×ATR**。所谓自适应带宽 → 就是一个紧得多的普通 SuperTrend。
- **② effATR 是纯破坏**：关掉后 **3/4 格变好**（BTC 4h 从 −41.03% → **+24.32%**，差 65pp），
  有效宽度同期从 1.31× 回到 2.16~2.19×。
- **③ TQI 调制在默认参数下是空转**：`tqiMult = 0.84 + 0.32·(1−tqi)^1.5`，理论零点 tqi = **0.370**；
  四格实测 TQI 均值 **0.374 / 0.388 / 0.387 / …** → tqiMult 均值 **0.997~1.002**，只在 ±15% 内摆动。
  → 号称最核心的引擎，在它的默认工作点上平均什么也没改。
- **④ character-flip 操作上等于不存在**：4.7 年 BTC 1h 只触发 **7 次**（4 格合计 1/1/2/7 次），
  且 **71% 与自然翻向冗余**（关掉它结果只差 0.03~0.9pp）。触发条件过苛（四因子均值一根跌穿 0.30）。
- **⑤ 带宽「时变」没有独立价值**：C5 精炼版（只留 TQI 时变带宽、去掉 effATR/不对称/charflip）
  打赢**它自己平均宽度对齐**的普通 ST 只有 **1/4**，另 3/4 落后 **24~36pp**。
  ⚠️ n=4 且 BTC 1h/4h 同源 → 符号检验没功效，只能说「没有任何一格支持它」，不能说「已证伪」。
- **⑥ 指标的「表现统计」是幸存者偏差（最狠的一条）**：持仓中遇新翻向会**静默覆盖旧单、永不记账**。
  BTC 1h 丢弃 **2531/3084 = 82%** 的信号，仪表盘胜率/平均R 只在剩下 18% 的「快结算」子样本上算。
  修正版（持仓中忽略新信号）与复刻版**符号相反**：ETH 4h +97.4% vs **−57.3%**。
- **⑦ fixed 口径下等于白做**：`10U×3x` 四格全部 **−0.1% ~ −0.9%**（3000 笔交易净亏不到 1%）。
- **⑧ vs 生产现役 ST(10,3.0)**：SATS 只赢 **1/4**（ETH 4h，且只有 0.68 年）。
- 同边帧内止损/止盈顺序（`sl_first`）几乎无影响（最多差 8pp，两格完全一致）。

## ⛔ 第零条：动任何回测之前，先核对"研究口径 == 生产口径"

本项目**并存两套回测**，混用会得出完全不同的结论：
- **`bt_*.py` / `backtest_engine.py`（637 行）= 真实出场**：内部直接调 `position.py` 状态机
  （TP1 +1.5% 平 70% → 抬保本 → 剩余 30% 跟超趋线）。
- **`sl2_*.py` = 简化出场**：翻向开仓、**下一反向翻向全仓平**，无分批/无保本/无跟踪。

→ **出场口径是第一主导变量，比任何入场过滤器都大一个量级。**
→ 逐年方向还相反：紧止盈赢震荡年（2022 +0.140%/笔，胜率 64%），趋势跟踪赢趋势年（2023/2026）。
→ 结论：**sl2_* 的任何结论都不能直接外推到生产，必须用 `backtest_engine.run_backtest` 复核。**

## ⚠️ 必须记住的工程约定

### 1. 训练与预测必须同特征、同顺序
训练时把 `ds["features"]` 原样存成 `features.json`；预测时按它逐列取值（缺失补 0、多余忽略），
**不要**用模块当前的 `FEATURE_COLS` —— 以后增删特征会让旧模型静默错位。
加载后再用 `booster.feature_name()` 交叉校验一次。

### 2. LightGBM 在 Windows 上不支持非 ASCII 路径
本项目根目录是 `D:\个人项目代码\...`（含中文），会直接踩到：
- `booster.save_model()` → `Model file ... is not available for writes`
- `lgb.Booster(model_file=...)` → `Could not open ...`

解法（见 `sl_v2.py` 的 `save_booster()` / `load_booster()`）：
先借道 `%TEMP%`（ASCII）保存/复制，再用 `shutil.move/copy` 搬回中文路径。
**任何**在本项目里读写 LightGBM / XGBoost 模型文件的地方都要走这层桥接。

### 3. 训练数据可离线
`build_dataset` 会向 OKX 翻页；把本地 JSON 灌进 `sl._CANDLE_CACHE[f"{symbol}|{tf}|{limit}"]`
即可离线复用（注意 key 里的 limit 必须等于实际根数）。
现有缓存：`backtest/btc_1h_full_fetched.json`（BTC 1h，36500 根，≈4.17 年）。
单次 `train`/`predict` 全流程约 3 分钟，瓶颈在 build_dataset。
数据集缓存 `ml_runs/_ds_cache/` 命中后降至 3~4 秒。

### 4. 研究结论（省得重复劳动）
- **方向类标签不可学**：BTC 1h 上 SuperTrend / UT Bot 全部 ≈ 随机入场，扣费后期望 = 手续费。
  36 组 tpsl 网格 AUC 全在 0.524~0.545；选择偏差校正置换 p=0.52。
- **波动率可学**（`btc_1h_vol50`，R²≈0.16），但**不能靠它赚钱**：
  · 波动率目标仓位 A/B/C 三方案全亏，且 **ML（C）输给纯 ATR（B）**；
  · 波动率过滤（`sl2_volfilter.py`）统计上真实（p<0.0033，单调、跨倍数、跨年份、抗 0.10% 费率），
    但**中位数不变（-0.70%）、有效广度只有 6 笔** → 只能当风控，不能当策略。
- **持有周期是一阶参数**：1h×3.0 四年费用 83.5pp（毛边际≈0，必死）；12h×4.0 只有 4.5pp。
  期望随周期上升，但**笔数同时塌缩到 45 笔** → 噪声。
- **BTC 单资产已封顶**：跨三个样本（BTC 4.17y / 4.73y / ETH 2.73y）共 43 个格子，
  **净均值 95%CI 下界 > 0 的：0 个；通过 Bonferroni 择时显著性：0 个；BTC 打败买入持有的：0/15**。
  BTC 买入持有 = +252.5% / 年化 35.3% / 回撤 -53.7%，**手续费归零也打不过**。
- **唯一跨样本复现**：波动率过滤器在 29 个可比格子中，
  逐笔期望 23/29 变好、**净值夏普同样 23/29**、Calmar 26/29（p=0.0030 / 0.0030 / <0.0001），
  且优于「等量随机删单」对照 24/29（随机删单夏普 -0.05 vs 实际 +0.42）。
  → **它是有信息量的交易过滤器，不是纯省手续费，也远非独立边际**：
  alpha t 值 0.48/0.09/1.23 全不显著；BTC 上夏普 0.28/0.01 打不过买入持有 0.85/0.57；
  过滤会把在场时间压到 26~29%。**只能当叠加在别的系统上的过滤器，不能单独用。**
- **ER（效率比）震荡过滤只在特定倍数上成立，不算机制**（`sl2_chop_filter.py`）：
  1h 上同一段数据三个倍数基线净值 **m=3.0 −83.2% / m=4.0 −92.3% / m=5.0 −51.5%（非单调）**；
  ER60 与逐笔净的 Spearman rho：BTC-USDT **m=3.0 −1.00 → m=4.0 −0.10 → m=5.0 +0.90**
  （BTC-JSON −0.90 → −0.20 → +0.50）。**方向两端都近极值却完全相反 = 由倍数决定，不是由"震荡"决定。**
  m=4.0 上 18 条规则夏普**全负**（最好 −0.14）、广度 0；m=5.0（1.8 笔/周）才是唯一为正的。
  「过滤优于等量随机删单」随倍数单调增强 17/39 → 23/39 → **32/39（m=5.0, p=0.0001）**，
  但 117 格最小 p=0.017 vs Bonferroni 4.27e-04 → **0 格通过**。
  → 结论：**"挑倍数/挑阈值"得到的任何好参数都是噪声**，必须靠多资产块自助判。
  评估口径新增 `spearman(ER档均值, 逐笔净)`，这是"震荡是否真的更差"的唯一可判定形式。
- **统一教训**：一律用 walk-forward + **选择偏差校正**的置换检验；  均值必须配中位数和「去最大 5 笔」一起看；报收益必须报"有效广度"；
  **必须有「随机入场 / 买入持有 / 等量随机删单」对照** —— 否则会把市场漂移或"少交易省手续费"
  当成择时能力。
  **多脚本共用一条规则时，规则必须只有一处实现**（曾因两处各写窗口导致同格结果 -0.621% vs +0.143%）。
  **百分数输入不要乘 100**（曾有 alpha 印成 +119%/月）。
  逐笔口径的月度序列**不能用「按平仓月归属」**（零值污染会把 beta/R² 假性压到 0），
  要用**逐根 K 线盯市**。

### 4. 评估口径必须用 walk-forward，且必须做选择偏倚校正
- **不能随机切分**：相邻信号的持仓区间大量重叠，随机切分 = 把未来标签漏进训练。
  用 `sl2_lab.walk_forward`（过去训 / 紧接着的未来测）。
- **先挑最好再看 p 值 = 必假阳性**。本项目实测：36 组 tpsl 网格挑出的最优 AUC=0.545，
  对单组做置换检验 p=0.0398（看着显著），但把"扫 36 组挑最大"纳入零分布后 **p=0.5246**。
  用 `sl2_lab permsweep`。**只要报告的是"扫了一批之后的最优"，就必须用这个。**

### 5. 数据上的既有结论（别重复试错）
- **方向类标签（fwd 方向 / tpsl）在 BTC 1h 上不可学**：AUC 0.47~0.545，扣费后期望全负。
- **波动率类标签可学**：未来波动率/当前ATR，walk-forward R²≈0.175，置换 p=0.005。
  已训练 `ml_runs/btc_1h_vol50/`。
- **SuperTrend 与 UT Bot 是同族**（ATR 棘轮移动止损，只差锚点与灵敏度），
  BTC 1h 上两者扣费后期望都≈ -0.10%（正好等于手续费）= 随机入场。
  换信号源不解决问题，要换的是**靶子**。

### 6. sl_v2 自定义标签
`--label-mode vol|mfe` 走回归。特征与标签无关，故用固定 tpsl 载体
（`_carrier()`）命中数据集缓存，换标签不用重建数据集。

### 7. 外部指标移植：运行时注入信号源，**不改任何现有文件**
要测「第三方的入场逻辑 + 我们的生产出场」时，不要改 `backtest_engine.py`。
`backtest_engine` 里只有一处取信号：`st = super_trend(...)`（`from indicators import super_trend`
在模块顶部绑定）。所以在**新脚本**里运行时替换即可：

```python
import backtest_engine as BE
_ORIG = BE.super_trend
BE.super_trend = lambda *a, **kw: _BOX["st"]      # 返回预先算好的序列
... run_backtest(candles, p, exit_rules=prod_rules(), full_tools=True)
BE.super_trend = _ORIG                            # 用回原实现跑基线
```

注入的序列必须返回 `backtest_engine` / `feed` 期望的契约：
`{"up","dn","trend","atr","flips"}`，长度 = K 线根数。
- `trend[i]`：`None` 表示未热身（引擎不会在此开仓）、否则 ±1
- `st_line(i) = up[i] if trend[i]==1 else dn[i]` → **up/dn 两处填同一个 stLine 值**最省事
  （多头段 stLine 必须在价格下方，空头段在上方，否则 `position.initial_stop` / `trail` 会算反）
- `flips` 的 `{"i","type"}` 里的 `i` 必须与 `trend` 实际变化的那一根严格一致
- 引擎内**先止损后止盈**（同根同时满足算止损）；自己的模拟器要与之一致才可比

⚠️ 踩过的坑：把「滚动和」误实现成「滚动均值」，会让 `ER = 净位移/路程` 放大 length 倍
（20 倍）→ ER 越界 → `legacyAdapt = 1+0.5(0.5−ER)` 变负数 → 带宽乘数变负 →
翻转带跑到价格错误的一侧 → **状态机每根 K 线来回翻**（34587 笔/4.7 年）。
这类错会伪装成「策略无效」而不是报错。**必须给中间量加自检**：ER∈[0,1]、带宽乘数>0。
